## 1. 问题陈述

暗色主题下，WYSIWYG 编辑区右侧出现 **Windows 经典原生滚动条**：白轨道、浅灰滑块、上下箭头按钮。与已落地的深色画布（`--bg-canvas` / `--bg-stage`）形成强对比，破坏「轻卡片式编辑画布」的一体感。

侧边栏树、笔记列表、预览区、目录、搜索结果等容器已使用细条 + `var(--border)` 自定义滚动条；**主编辑滚动容器未覆盖**，体验不一致。

### 1.1 用户可感知现象

- 暗色 WYSIWYG（Milkdown）长文滚动时，右侧出现刺眼白条
- 源码模式（CodeMirror `.cm-scroller`）同样可能露出原生条
- 亮色主题下原生条相对不突兀，但粗细、箭头与侧栏细条仍不统一

### 1.2 非问题（本 PRD 不覆盖）

- 深色画布底色、卡片描边、工具栏配色（已由 dark-mode editor canvas 落地）
- 滚动性能、虚拟列表、同步滚动逻辑
- 自定义滚动条组件 / 第三方 scrollbar 库

## 2. 用户与场景

| 角色 | 场景 | 期望 |
| --- | --- | --- |
| 暗色主题写作者 | 在 WYSIWYG 中编辑长笔记并滚动 | 滚动条颜色融入画布，不抢视线 |
| 源码模式用户 | 在 CodeMirror 中滚动长 Markdown | 与 WYSIWYG / 预览观感一致 |
| 预览 / 分屏用户 | 预览区或分屏同时滚动 | 各栏滚动条同宽、同色、无箭头 |
| 亮色主题用户 | 日常滚动侧栏与正文 | 不出现过深滑块；风格仍是细条 |

---

## 3. 目标与非目标

### 3.1 目标

1. **暗色主题下所有可滚动区域不再出现 Windows 经典白轨道 + 箭头**
2. **全应用滚动条视觉统一**：宽度、滑块色、轨道透明，跟随现有 Design Token
3. **亮/暗主题自动适配**，不维护两套硬编码颜色
4. **改动可测**：架构约束守住 `color-scheme` 与全局滚动条规则，避免再次漏配

### 3.2 非目标

- 不引入滚动条组件库或自绘 overlay scrollbar
- 不改变滚动容器的 overflow 职责（谁滚谁继续滚）
- 不做 macOS overlay 风格的「悬停才显示」交互（可作为后续 polish）
- 不改 uTools / Electron 宿主原生窗口滚动条（应用内 `body` 已 `overflow: hidden`）

## 4. 需求说明

### 4.1 功能需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| R1 | 暗色主题下，`.milkdown-host`（WYSIWYG）滚动条使用主题色，无白轨道、无上下箭头 | P0 |
| R2 | 暗色主题下，`.cm-scroller`（源码）滚动条与 R1 一致 | P0 |
| R3 | 已有自定义滚动条的区域（侧栏、预览、TOC、搜索、语言下拉、页签横滚）与全局规则对齐，避免两套粗细 | P1 |
| R4 | 其它 `overflow: auto` 区域（导入弹窗、设置等）一并覆盖，禁止再各写一份选择器 | P1 |
| R5 | `html` / 主题根节点声明 `color-scheme`，使 Chromium 原生控件走对应色系 | P1 |
| R6 | Firefox 通过 `scrollbar-width` / `scrollbar-color` 获得同等细条观感 | P2 |

### 4.2 体验需求

| ID | 需求 |
| --- | --- |
| E1 | 滑块默认低对比、hover 略提亮，不使用 `--primary` 以免像强调控件 |
| E2 | 轨道透明或接近画布底，避免再出现「一条白缝」 |
| E3 | 宽度建议 6px（比现侧栏 4px 更易拖）；若产品坚持与侧栏完全一致，可统一为 4px，但必须全局同一值 |
| E4 | 亮色主题滑块使用 `--border` 系，不得明显深于正文 |

### 4.3 约束

- 遵循 `AGENTS.md`：样式收口 `src/style.css`，不引入平行 CSS 框架
- Token 放在 `:root` / `[data-theme="dark"]`，与现有 `--bg-*` / `--border` 体系一致
- TDD：先补架构测试，再改 CSS

## 5. 验收标准

- [ ] 暗色 WYSIWYG 长文：右侧为细条主题色滑块，无白轨道、无箭头
- [ ] 暗色源码模式：`.cm-scroller` 观感与 WYSIWYG 一致
- [ ] 暗色预览 / 侧栏 / TOC / 搜索：与编辑区同宽同色
- [ ] 亮色主题：滑块可见但不突兀，无过深灰条
- [ ] 横向滚动（页签栏、宽表格）同样走全局细条，无白色横条
- [ ] 架构测试断言 `[data-theme="dark"]` 含 `color-scheme: dark`，且存在全局 `::-webkit-scrollbar` / `scrollbar-color`
- [ ] 相关架构测 + 全量回归通过

---

## 6. 成功指标

本项为视觉缺陷修复，不以 DAU 衡量。交付以**定性验收**为准：

- 暗色截图中编辑区右侧不再出现系统默认白滚动条
- 代码层面不再对单个列表容器重复粘贴 `::-webkit-scrollbar` 规则（历史重复可在实施时收敛）

## 7. 范围

| 在范围内 | 不在范围内 |
| --- | --- |
| 全局滚动条 Token + WebKit / Firefox 规则 | 滚动位置记忆、同步滚动算法 |

| Milkdown / CodeMirror / 预览 / 侧栏 / 弹层 | 自定义滚动条 JS 组件 |
| 架构测试与文档 | Windows 系统级滚动条设置 |

---

## 8. 风险（产品侧）

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 滑块过细难拖 | 4px 在 Windows 上命中面积小 | 默认 6px；Token 可调 |
| 只修编辑区、弹层仍白条 | 用户会认为「没修完」 | 必须全局规则，禁止只补 `.milkdown-host` |
| `color-scheme` 影响原生控件 | 少数系统控件外观变化 | 可接受；与暗色主题一致才是目标 |
