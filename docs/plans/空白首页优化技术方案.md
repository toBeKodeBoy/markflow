## 落地状态

- 状态：**已落地（待评审）**

- 关联 PRD：[`docs/prds/空白首页优化.md`](../prds/空白首页优化.md)

### 本文档目的

把空白首页从「关光标签后的弱空态」做成**空库首启主路径**：改启动引导、拆空态组件、前置导入、模板 / 教程 / 示例库、一次性引导气泡。严格按 Phase A → D 交付。

### 非目标（本轮实现）

- 不改 `utools.dbStorage` 为磁盘 Markdown 仓库
- 不在顶栏加主题切换
- 不引入引导组件库 / 新 UI 库
- 不做快捷键浮窗（PRD §8）

## 1. 问题背景

### 1.1 空态几乎不是首启路径

[`src/stores/editorTabs.ts`](../../src/stores/editorTabs.ts) 在无 Tab 且无笔记时会创建欢迎笔记：

```376:384:src/stores/editorTabs.ts
  function bootstrapAfterLoad(): void {
    if (tabs.value.length > 0) return
    const noteStore = useNoteStore()
    if (noteStore.noteList.length > 0) {
      openTab(noteStore.noteList[0].id)
    } else {
      openWelcomeTab()
    }
  }
```

`openWelcomeTab()` 调用 `createNoteWithContent(WELCOME_NOTE_CONTENT)`，所以新用户直接进入编辑器，看不到 [`App.vue`](../../src/App.vue) 的 `empty-tabs-state`。

空态目前只在 `closeAllTabs()` 之后稳定出现（见 `tests/integration/editor-tab-empty-state.test.ts`）。删除最后一枚 Tab 的 `removeTabSilently()` 在 `tabs.length === 0` 时也会再 `openWelcomeTab()`。

### 1.2 空态信息不足

```34:40:src/App.vue
            <div v-if="!hasOpenTabs" data-testid="empty-tabs-state" class="empty-tabs-state">
              <h2 class="empty-tabs-title">当前没有打开的笔记</h2>
              <p class="empty-tabs-text">你可以新建一篇笔记，或者从侧边栏重新打开已有内容。</p>
              <div class="empty-tabs-actions">
                <button class="btn-primary" @click="createModalVisible = true">新建笔记</button>
                <button @click="sidebarVisible = true">从侧边栏打开</button>
```

导入能力已在 [`Toolbar.vue`](../../src/components/Toolbar.vue) 的 `importNote()`，空态无法复用。底栏无条件渲染 `{{ charCount }} 字`。

### 1.3 存储模型

生产环境笔记在 `utools.dbStorage`（[`public/preload.js`](../../public/preload.js)），开发回退 `localStorage`。不存在 `Documents/MarkFlow笔记`。侧栏「最新 / 我的文件夹 / 回收站」已是系统结构。`sidebarVisible` 默认已是 `true`。

## 2. 根因分析

| 事实 | 结论 |
| --- | --- |
| 无笔记时强制 `openWelcomeTab()` | 空态被启动逻辑吃掉，改文案不够 |
| 导入逻辑写死在 Toolbar | 空态前置导入必须抽公共函数 |
| 欢迎正文只在自动创建时出现 | 应改为顶栏「新手教程」按需打开 |
| 原始建议写死 Documents 路径 | 文案必须收口常量，并用架构测试锁住 |

结论：这是**启动策略 + 空态信息架构**问题，不是再往 `empty-tabs-state` 堆两个按钮。

---

## 3. 目标

- 空库首启：`tabs.length === 0` 且 `noteList.length === 0` → 渲染空态，不写库
- 有笔记但无 Tab：同一空态组件，按 PRD E6 降噪
- 空态 UI 与原型 02 / 01 分层对齐；引导与示例库可插拔
- `App.vue` 只做编排，不承载四层空态 DOM

## 4. 方案设计

### 4.1 启动与关 Tab 策略

| 场景 | 现行为 | 目标行为 |
| --- | --- | --- |
| 空库冷启动 | 创建欢迎笔记并打开 | **停在空态** |
| 有笔记、无已存 Tab | 打开 `noteList[0]` | 保持（恢复工作现场） |
| `closeAllTabs()` | 空态 | 保持 |
| 删光当前 Tab 且库仍有笔记 | `openWelcomeTab()` 再造一篇 | **空态**或打开最近一篇；**禁止**再造欢迎稿 |
| 删光库内最后一篇 | 视路径而定 | **空态** |

`openWelcomeTab()` 保留为「新手教程」的实现，但改成：

1. 若设置里有 `tutorialNoteId` 且该笔记仍存在 → `openTab(id)`
2. 否则 `createNoteWithContent(WELCOME_NOTE_CONTENT)`，把 id 写入设置，再打开
3. 用户删掉教程笔记后，下次点击再创建一次

建议将函数重命名语义为 `openTutorialNote()`，`openWelcomeTab` 作别名以免一次性改爆测试。

### 4.2 组件拆分

```
src/components/EmptyHome.vue          # 空态四层 UI（A 期可先做精简槽）
src/components/OnboardingCoach.vue    # C 期：气泡 + 1/3 + 跳过 + 勾选
src/composables/useOnboarding.ts      # 是否展示、当前步、dismiss 持久化
src/composables/useImportMarkdown.ts  # 从 Toolbar.importNote 抽出选文件 + 导入
src/constants/noteTemplates.ts        # 4 份模板 Markdown
src/constants/exampleLibrary.ts       # 示例文件夹 + 笔记种子
src/constants/emptyHomeCopy.ts        # 标题/副标题/提示文案（禁止伪路径）
src/constants/welcomeNote.ts          # 升级为教程正文，增加 <!-- markflow:tutorial --> 标记
```

`App.vue`：`v-if="!hasOpenTabs"` 时挂 `EmptyHome`，传入 `isEmptyLibrary`；C 期再挂 `OnboardingCoach`。

`Toolbar.vue`：B 期在「目录」与设置之间加「新手教程」，`data-testid="toolbar-tutorial-btn"`，并给「新建」「搜索」加 `data-onboarding="create|search"`。

`Sidebar.vue`：「我的文件夹」行加 `data-onboarding="my-folder"`；D 期底栏增加 `data-testid="sidebar-storage-caption"`。

### 4.3 设置字段

在 [`AppSettings`](../../src/types/index.ts) 增加：

```ts
/** 空库新手引导是否已关闭（跳过或勾选不再展示） */
onboardingDismissed?: boolean
/** 按需创建的新手教程笔记 id */
tutorialNoteId?: string | null
/** 示例知识库是否已导入（幂等） */
exampleLibraryImported?: boolean
```

默认：三项均视为未完成。`useStorage().defaultSettings()` 不必强制写出，读取时按 `=== true` 判断即可。

不把「是否首启」编码成单独字段：用 `noteList.length === 0 && !onboardingDismissed` 即可。有笔记即视为老用户。

### 4.4 导入复用

新建 `useImportMarkdown()`：

```ts
async function importMarkdownToActiveFolder(): Promise<boolean>
```

内部逻辑从 `Toolbar.importNote` 原样搬迁（uTools `openMarkdownFile` / 浏览器 `<input type="file">` → `store.importMarkdownFile` → `tabsStore.openTabForNewNote`）。Toolbar 与 EmptyHome 都调用它，禁止复制一份 file picker。

### 4.5 模板创建

`noteTemplates.ts` 导出：

```ts
export type NoteTemplateId =
  | 'tech-doc'
  | 'study-note'
  | 'journal-plan'
  | 'agent-prompt'

export const NOTE_TEMPLATES: Array<{
  id: NoteTemplateId
  title: string
  description: string
  content: string
}>
```

点击：`createNoteWithContent(content, store.activeFolderId ?? undefined)` → `openTabForNewNote`。标题由正文 H1 提取，与现有创建路径一致。

正文放常量文件，不写进 Vue。

### 4.6 示例知识库

`exampleLibrary.ts` 描述树，例如：

```
技术学习笔记/
  接口文档示例.md
  故障排查记录.md
AI Agent教程/
  提示词模板示例.md   ← 导入后默认打开
  ...
随笔归档/
  今日计划示例.md
```

`importExampleLibrary()`（放 `src/utils/exampleLibrary.ts` 或 note store 旁的纯函数 + store 调用）：

1. 若 `exampleLibraryImported === true` 且三文件夹仍在 → 通知「示例知识库已存在」，展开并打开约定笔记
2. 否则按名查找文件夹，缺则 `createFolder`；缺笔记则 `createNoteWithContent(..., folderId)`
3. `save({ exampleLibraryImported: true })`
4. 展开祖先、打开「提示词模板示例」

幂等按**文件夹名 + 笔记标题**判断，不依赖易变 id。用户删光示例后允许再导入（此时把 flag 视为失效：三文件夹都不在则允许重建）。

### 4.7 引导气泡

不引入 intro.js。`OnboardingCoach.vue` 用 `document.querySelector('[data-onboarding="..."]')` 取 `getBoundingClientRect()`，`position: fixed` 画气泡。窗口 resize / 侧栏宽度变化时重算。

三步顺序固定。当前步高亮对应锚点即可，不做全屏 modal。

持久化：`onboardingDismissed: true` 在「跳过」或勾选「不再展示」时写入。未勾选但走完 3 步也视为完成。

展示条件（同时满足）：

- `!settings.onboardingDismissed`
- `noteStore.noteList.length === 0`
- `!hasOpenTabs`

### 4.8 状态栏

```vue
<span v-if="hasOpenTabs" class="status-bar-right">{{ charCount }} 字</span>
```

无 Tab 时左侧 `saveStatusText` 已是空串，可显示「就绪」或留空，与原型 01 一致即可。

### 4.9 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 继续自动欢迎笔记，只改欢迎正文 | 空态、模板卡、导入前置全部不可达 |
| 空态 DOM 继续堆在 `App.vue` | 违反目录职责，后续引导 / 模板会把页面撑爆 |
| 首次静默 `createFolder` 三套目录 | 污染用户库；PRD 已改为点击导入 |
| 侧栏展示 `utools.getPath('documents')` | 不是笔记真实位置 |
| 3 秒自动关掉气泡 | 原型 03 要求可控；过短等于没看见 |

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 改 `bootstrapAfterLoad` 导致集成测试大面积失败 | 先补/改启动测试再改实现；欢迎笔记改为教程入口 |
| `removeTabSilently` 仍造欢迎稿 | 与 bootstrap 同一策略函数 `ensureEmptyOrRestore()`，避免两处分叉 |

| Toolbar 抽出导入后漏测浏览器分支 | composable 单测分别 mock `window.markflow` 存在/不存在 |
| `EmptyHome.vue` 超过 800 行 | 模板卡抽 `EmptyHomeTemplateCard.vue`；文案全部常量 |

## 9. 结论

空白首页优化的第一刀是 **停掉空库自动 `openWelcomeTab()`**，否则任何 UI 都不会出现在首启。

第二刀是 **把空态做成独立组件 + 文案常量**，导入抽 composable，模板 / 示例库当数据而不是页面里的 Markdown 字符串。

视觉以 `docs/plans/ui` 四张原型为准；存储相关文案必须以 uTools 本地数据库为准，并用架构测试禁止伪路径回潮。
