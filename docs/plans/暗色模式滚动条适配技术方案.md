# 暗色模式滚动条适配技术方案

## 落地状态

- 状态：**待实施**
- 文档日期：2026-08-13
- 关联 PRD：[`docs/prds/暗色模式滚动条适配.md`](../prds/暗色模式滚动条适配.md)
- 关联画布约束：`tests/architecture/dark-mode-editor-canvas.test.ts`

### 本文档目的

把 PRD 中的「暗色滚动条不适配」落成可实施的 CSS / 测试方案：统一 Token、全局 WebKit + Firefox 规则、`color-scheme`，并收敛现有散落选择器。

### 非目标（本轮实现）

- 不引入滚动条组件库
- 不改 overflow 归属（`.milkdown-host` / `.cm-scroller` / `.preview-content` 仍各自滚动）
- 不做悬停才显示的 overlay 交互

---

## 1. 问题背景

用户在暗色 WYSIWYG 下看到编辑区右侧 **Windows 经典原生滚动条**（白轨道、浅灰滑块、上下箭头），与深色画布冲突。

滚动发生在 [src/style.css](../../src/style.css) 的 `.milkdown-host`：

```2612:2616:src/style.css
.milkdown-host {
  flex: 1;
  overflow-y: auto;
  height: 100%;
}
```

该容器**没有** `::-webkit-scrollbar` 规则。源码模式 `.cm-scroller` 的 `overflow: auto` 写在 [src/components/Editor.vue](../../src/components/Editor.vue) 的 `EditorView.theme` 中，同样未配滚动条样式。

全仓也未声明 `color-scheme`（仅 `useTheme.ts` 用 `prefers-color-scheme` 读系统偏好）。uTools 宿主为 Chromium，未设 `color-scheme: dark` 时走系统浅色原生条。

---

## 2. 根因分析

| 事实 | 结论 |
| --- | --- |
| 侧栏 / 预览 / TOC / 搜索 / 语言下拉已有 `::-webkit-scrollbar { width: 4px }` + `thumb: var(--border)` | 设计语言已存在，只是未全局化 |
| `.milkdown-host`、`.cm-scroller`、导入弹窗等 `overflow: auto` 未覆盖 | 主编辑区漏配，露出系统条 |
| 无 `color-scheme` | Chromium 原生条、部分表单控件不跟随 `data-theme` |
| 规则复制了 6+ 处 | 再给编辑区单独抄一份会继续碎片化 |

结论：不是主题 Token 错了，而是**滚动条样式没有收口到主题层**。

---

## 3. 目标

修复后需满足：

- 暗色下所有可滚动区域使用主题细条，无白轨道、无箭头
- 亮/暗通过 CSS 变量自动切换
- 一处定义、全局生效；历史局部规则可删可留，但不得与全局冲突
- 架构测试锁住 `color-scheme` 与全局滚动条选择器

---

## 4. 方案设计

### 4.1 采用：全局 Token + `color-scheme` + WebKit / Firefox 双轨

在 `src/style.css` 主题变量区新增滚动条 Token，并在 Reset 附近写全局规则。

**Token（`:root`）**

```css
:root {
  color-scheme: light;
  --scrollbar-size: 6px;
  --scrollbar-thumb: color-mix(in srgb, var(--border) 88%, var(--text-muted));
  --scrollbar-thumb-hover: var(--text-muted);
}

[data-theme="dark"] {
  color-scheme: dark;
}
```

暗色块无需重写 thumb 色：`--border` / `--text-muted` 已在 `[data-theme="dark"]` 覆盖。

**全局规则（Reset 后）**

```css
* {
  scrollbar-width: thin;
  scrollbar-color: var(--scrollbar-thumb) transparent;
}

*::-webkit-scrollbar {
  width: var(--scrollbar-size);
  height: var(--scrollbar-size);
}

*::-webkit-scrollbar-track {
  background: transparent;
}

*::-webkit-scrollbar-thumb {
  background: var(--scrollbar-thumb);
  border-radius: 999px;
}

*::-webkit-scrollbar-thumb:hover {
  background: var(--scrollbar-thumb-hover);
}

*::-webkit-scrollbar-button {
  display: none;
  width: 0;
  height: 0;
}
```

| 机制 | 作用 |
| --- | --- |
| `color-scheme: dark` | 通知 Chromium / 系统控件走暗色原生条；表单控件一并适配 |
| `::-webkit-scrollbar*` | uTools Chromium 上真正改颜色、去箭头的可靠手段 |
| `scrollbar-color` / `scrollbar-width` | Firefox 回退 |
| `::-webkit-scrollbar-button { display: none }` | 去掉 Windows 经典上下箭头 |

**CodeMirror 权重**

`.cm-scroller` 的 overflow 来自 `EditorView.theme` 内联主题。全局 `*` 选择器足够覆盖滚动条伪元素；若实测被主题样式挡住，再补：

```css
.cm-host .cm-scroller::-webkit-scrollbar { width: var(--scrollbar-size); }
```

不必把滚动条颜色写进 `Editor.vue`。

### 4.2 收敛历史局部规则

下列选择器与全局重复，实施时删除或改为只保留「需要更窄」的例外（本轮默认删除，统一 6px）：

- `.sidebar-tree::-webkit-scrollbar` / `-thumb`（约 L727）
- `.note-list::-webkit-scrollbar` / `-thumb`（约 L748）
- `.preview-content::-webkit-scrollbar` / `-thumb`（约 L1835）
- `.code-lang-dropdown-list::-webkit-scrollbar` / `-thumb`（约 L2843）
- `.toc-list::-webkit-scrollbar` / `-thumb`（约 L3261）
- `.search-modal-results::-webkit-scrollbar` / `-thumb`（约 L3444）
- `.editor-tab-bar-scroll` 仅有 `scrollbar-width: thin` 与 `height: 4px`，改为继承全局（横滚用同一 `--scrollbar-size`）

### 4.3 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 只加 `color-scheme: dark` | Windows 经典条（白轨道 + 箭头）在 Electron/uTools 上经常改不干净 |
| 只给 `.milkdown-host` / `.cm-scroller` 抄预览区 4px 规则 | 弹层、导入列表仍会露白条；继续复制粘贴 |
| 自绘滚动条组件 | 成本高，与现有细条风格不匹配，违反「不引入平行 UI」 |

## 5. 实现要点

### 5.1 改动文件

| 文件 | 变更 |
| --- | --- |
| `src/style.css` | Token、`color-scheme`、全局滚动条；删除 6 处局部重复 |
| `tests/architecture/dark-mode-editor-canvas.test.ts`（或新建 `dark-mode-scrollbar.test.ts`） | 架构约束 |
| 本文档 / PRD | 落地后回写状态 |

不改 Vue 组件逻辑，不改 `useTheme.ts`（`data-theme` 已足够驱动 CSS）。

### 5.2 `color-scheme` 放置

写在 `:root` 与 `[data-theme="dark"]`，与现有主题切换一致：

```12:14:src/composables/useTheme.ts
    isDark.value = dark
    document.documentElement.setAttribute('data-theme', dark ? 'dark' : 'light')
```

不要写死在 `body` 上另开一套。

### 5.3 宽度决策

PRD 默认 **6px**（`--scrollbar-size`）。若评审要求与旧侧栏完全一致，只改 Token 为 `4px`，不要再写死在各选择器里。

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 全局 `*` 误伤某插件内部滚动条 | Milkdown / CM / hljs 均走应用主题；若第三方画布需要原生条，再加例外选择器 |
| CodeMirror 内联主题盖住伪元素 | 实测后用 `.cm-host .cm-scroller` 补权重，颜色仍用 Token |
| `color-scheme` 改变原生 `<select>` / 滚动条箭头残留 | WebKit 规则强制去 button；手测设置页 select |
| 4px → 6px 侧栏观感变化 | Token 一处可回退；架构测只锁「存在 size 变量」，不锁具体像素（若产品要锁 6px 再改断言） |

## 9. 结论

主编辑区漏配滚动条样式，叠加未声明 `color-scheme`，使 uTools/Windows 露出经典浅色原生条。

正确做法是**主题层一次收口**，而不是再给 `.milkdown-host` 抄一份 4px 规则。`color-scheme` 与 `::-webkit-scrollbar` 必须同时做：前者对齐系统控件，后者保证 Chromium 下去掉白轨道和箭头。
